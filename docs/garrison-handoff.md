# Garrison Step handoff (MOO-72 Commit 9)

This is the one place the Garrison Step (MOO-44) should start reading. It
does not replace the four detailed docs it cross-references below — those
remain the backing material — but consolidates every open uncertainty
this construction ticket (MOO-72) identified into one matrix, and adds the
one genuine gap none of them cover: whether the tool actually helps review
a real pull request.

Per MOO-66/MOO-72's own scoping rule, this document **identifies**
uncertainties and proposes how to test them — it does not resolve any of
them. Resolving these is explicitly MOO-44's job, not this construction
ticket's.

## Test matrix

| Function-flow correctness | `for...else` is dropped upstream by `@codevisualizer/core` itself. No callee drill-down (caller-side only). No full-text search, match-cycling, or directional emphasis beyond drawn edges ("Raven patterns" from the original ticket — no analog exists anywhere in this codebase today). No node-budget reduction *within* a chosen depth mode (only coarser/finer mode selection exists). | Do any of these block real use, or are they cosmetic? | PR-review usefulness | **Nothing evaluates this anywhere in the codebase or its docs.** This is the *original stated project goal* — the Code Reality Layer project description's own initial-milestone outcome is "a working visualization workflow that materially improves review of at least one real pull request" — and it has never actually been tested end-to-end. | Used on a real, open PR with a non-trivial diff, does the tool change what a reviewer actually catches, or how quickly they understand the change, compared to reviewing without it? | A real PR touching multiple files, with at least one function-level behavior change (exercises repository → file → function drill-down together) | A reviewer's own before/after notes: specifically what they would have missed, misread, or taken longer to understand without the tool | Materially helped → validates the core premise the whole project rests on. Didn't help → this is the single most important signal in this entire handoff; name it plainly rather than assume success because the construction work is otherwise done. | *(new — no existing doc; this document is the first place this question is written down)* |

## What this handoff deliberately does not do

- **No new fixtures were built.** Every "known baseline" above traces to a fixture or analysis that already exists in this repository; nothing was added to make this document look more complete.
- **No synthetic scoring system was invented**, especially not for "PR-review usefulness" — assigning it a number here would be exactly the kind of premature product judgment MOO-66 scopes away from construction tickets and reserves for the Garrison Step.
- **No aesthetic or density question was resolved** — every "decision/exit criterion" column describes how MOO-44 would decide, not what the answer is.
